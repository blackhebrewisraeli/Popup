end: start → capture → finish → saved Research results → evidence → Manual Spot scenario, for
`crypto-usdt-v1` on `main` at `6e99803` (#154). It checks that the software path repeats and that
Research represents what was retrieved. It says nothing about whether a rank, setup or scenario is
economically useful or profitable.

price, per-pair score or account value is recorded here, and no screenshot is attached, because

## Findings

- **No code defect** blocked or misrepresented the workflow, so no code changed.
- **Fixed (documentation):** the runbook prompt the owner pastes ([MARKET_SCANNER.md](MARKET_SCANNER.md#refreshing-it-owner-runbook))
  had no crypto start command and no instruction for a short result shown inline. Every crypto
  run hits that case while GRAM and HYPE are young, and the prompt otherwise leaves an agent to
  stop, retype (forbidden) or record a misleading failure. It now names
  `--universe crypto-usdt-v1`, the byte-for-byte copy or `tradingview-fail`, and why a crypto
  finish reports `PARTIAL` with a non-zero exit.
- **For the owner to decide** (C7, C12): whether **Scan shown** should survive a page reload,
  and whether an in-app reload of an unchanged file should also clear scenario inputs. Both are
  current, documented behaviour; neither confuses the scan's identity or evidence.

## Not performed

No model, threshold, Pine, scanner version, universe or frozen-study change; no parameter

is not prospective and nothing was reconstructed.

## Follow-up, 2026-11-12: C7 fixed, C12 requirement revised

Recorded after the run above, on `main` `134fef7` (#155) plus this branch. The rows above stay as
observed: C7 and C12 failed then. Owner decisions:

- **C7, change it.** A full page reload restores the source and **Scan shown** chosen in that
  tab. The tab's `sessionStorage` holds only the source and a scan ID (`vite dev` only), and the
  scan is read again; a missing, unreadable, refused or malformed one says so and offers **Show
  the latest published scan**, never another source or scan by itself.
- **C12, keep it, with a revised requirement.** An in-app reload of an identical file may keep the
  selection and scenario inputs. Changed content resets them, even under the same scan ID: the
  review is now keyed by a digest of what was read, not by scan ID, import time and baseline.

No fresh retrieval: the browser checks used the existing local scans, read only, and both stores
were byte-identical (330 files) before and after. Unit tests use labeled synthetic fixtures.
